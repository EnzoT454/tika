# V6 — Expression régulière contrôlée par le document (CWE-1333)

`tika-core/.../parser/RegexCaptureParser.java` applique normalement des motifs choisis dans sa configuration aux lignes du document. Ce fichier est pertinent pour franchir explicitement la frontière entre configuration de confiance et données analysées.

La modification ajoute volontairement un format de première ligne `regex:MOTIF`. Le contenu du document est alors transmis à `compileInlinePattern(String)` puis à `Pattern.compile`, sans restriction du langage de motifs, taille maximale ou limite de temps. Le matcher est appliqué aux lignes suivantes dans le chemin réel de `parse`. Le code tente d'écrire le marqueur `X-TIKA:INLINE_MATCH`, mais cette écriture String est refusée par la protection des espaces réservés de `Metadata`. L'absence du marqueur n'est donc pas un indicateur fiable de l'absence de correspondance. Il ne s'agit pas d'une nouvelle méthode inutilisée ni d'une simple reformulation d'un risque de configuration préexistant : le document peut désormais choisir lui-même le motif.

Un auteur de document peut fournir un motif à retours arrière coûteux et une longue ligne défavorable, ce qui peut monopoliser le thread d'analyse ou épuiser sa pile. Le risque suppose que le document soit traité par ce parser, et dépend du motif et du moteur Java ; toute expression n'est pas dangereuse. L'ajout de cette fonctionnalité pédagogique, qui n'est pas une convention Tika préexistante, est lui-même le défaut introduit.

La règle INFO `java-pattern-from-string-parameter` ajoute une alerte : cumul V1–V6, 23 résultats. C'est une règle d'audit à interpréter. Le contrôleur local compare également les INFO et ne filtre pas cette sévérité. Le build complet réussit avec 964 tests core et 8 processeur réussis, deux désactivations initiales, zéro violation Checkstyle et sources inchangées.

Correction : ne pas interpréter les documents comme des motifs ; conserver les motifs de configuration validés, utiliser un moteur sans backtracking lorsque possible et imposer des limites adaptées. La preuve comportementale bornée utilise seulement quatre caractères ; elle doit confirmer l'entrée contrôlée sans prétendre mesurer un épuisement de ressources.

**Validation comportementale incomplète.** Les traces `../behavior/results.json` et `validation-finale-20261112/` restent négatives pour l'indicateur V6. La seconde confirme pourtant deux LF et deux lignes : le diagnostic antérieur attribuant certainement l'échec aux sauts de ligne n'est pas soutenu par ces résultats. La lecture de `Metadata.set`, `blockReservedKeyWrite` et `ReservedNamespaces` identifie statiquement le rejet du marqueur réservé. Un observateur adapté reste à vérifier, sans contourner cette protection ni modifier ici le code de production. Voir [le bilan documentaire](../consolidation-20261112/README.md). Aucune nouvelle sonde n'a été exécutée pendant cette consolidation.
